# cc-agent — Pre-built Binaries

This directory contains pre-built, statically linked binaries of the CronCommander agent.

## Naming Convention

Binaries follow the format:

```
cc-agent-{VERSION}-{OS}-{ARCH}
```

Where:
- **VERSION**: Dashed version number (e.g. `1-1-0` for v1.1.0)
- **OS**: `linux`, `darwin` (macOS), `freebsd`
- **ARCH**: `amd64`, `arm64`, `386`

## Example

```
cc-agent-1-1-0-linux-amd64      # Linux x86_64
cc-agent-1-1-0-linux-arm64      # Linux ARM64 (Raspberry Pi, AWS Graviton)
cc-agent-1-1-0-darwin-arm64     # macOS Apple Silicon
cc-agent-1-1-0-freebsd-amd64   # FreeBSD x86_64
```

## How These Are Built

Binaries are generated by running `make publish` from the `cc-agent/` directory. The version is read from the root `VERSION` file and embedded into:

1. **Filename** — for release identification
2. **Binary** — via `go build -ldflags "-X main.Version=..."` so that `cc-agent --version` reports correctly

## Usage

Download the appropriate binary for your platform, make it executable, and run:

```bash
chmod +x cc-agent-1-1-0-linux-amd64
sudo cp cc-agent-1-1-0-linux-amd64 /usr/local/bin/cc-agent
cc-agent --version
```

Or use the automated installer:

```bash
curl -sSL https://croncommander.com/install.sh | bash
```

## Versioning

The version is managed centrally in `/VERSION` at the project root. Before
every build, review the changes and increase the version using semantic
versioning. Never deploy or publish a changed binary under a previously used
version.

To create a new release:

1. Review the changes and update `/VERSION` with the appropriate major, minor,
   or patch increase
2. Run `make publish`
3. New binaries appear here with the updated version in the filename
